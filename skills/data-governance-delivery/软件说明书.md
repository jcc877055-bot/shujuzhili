# 企业数据资产治理与数据质量闭环管理全流程 Skill 软件说明书

## 1. 软件概述

本 Skill 用于指导 AI 按软件工程顺序完成“企业数据资产治理与数据质量闭环管理系统”的课程报告与工程交付。它以总任务台账、实际文档、代码、测试和部署结果为依据，通过阶段门禁避免跳步、漏项和虚构完成状态。

项目技术栈固定为 Vue 3、Vite、Element Plus、Java 17、Spring Boot 3 和 MySQL 8，采用前后端分离、RESTful API 与 Git 版本管理。

## 2. 适用对象

- 软件工程课程项目学生与指导教师
- 负责需求、设计、开发、测试、部署和验收的项目成员
- 需要让 AI 持续推进并审计完整软件工程交付物的团队

## 3. 核心能力

- 建立和维护总任务台账
- 完成四个课堂报告及汇报前检查
- 建立业务定位、业务结构和质量问题工单闭环
- 将业务分析转换为带唯一编号的系统需求
- 在编码前完成测试计划、场景、用例和验收标准
- 设计并验证 PC Web 原型
- 完成架构、数据库、接口、权限、审计和部署设计
- 指导 Vue 3 与 Spring Boot 3 分模块开发和验证
- 执行系统测试、部署准备与需求验收
- 盘点并审计 12 至 27 份软件工程文档

## 4. 包内文件

| 文件 | 用途 |
|---|---|
| `SKILL.md` | Skill 主定义，包含触发条件、阶段流程、交付物和质量门禁 |
| `README.md` | 快速使用入口 |
| `软件说明书.md` | 面向使用者的软件功能、安装和使用说明 |
| `发布清单.md` | 发布前后的核验记录 |

## 5. 安装方式

将整个 `data-governance-delivery` 文件夹复制到 Codex 技能目录中，并保持 `SKILL.md` 位于该文件夹根目录。重新开始会话或刷新技能后即可使用。

若只在当前项目中使用，也可以保留在仓库的 `skills/data-governance-delivery/` 下，由项目成员共同维护。

## 6. 运行前提

建议项目根目录具备：

- `总任务台账.md`
- `docs/` 文档目录
- 前端、后端、数据库、测试和部署相关目录
- 可读取的 Git 仓库状态

缺少其中某项时，Skill 会将其登记为缺项，而不是假定已经完成。

## 7. 使用方法

首次运行建议输入：

> 使用 data-governance-delivery Skill，读取总任务台账和 docs，执行启动盘点与 S01。只在质量门禁通过后进入 S02。

继续开发可输入：

> 使用 data-governance-delivery Skill，从总任务台账中最早未完成且依赖已满足的任务继续。

最终检查可输入：

> 使用 data-governance-delivery Skill 执行 S11，核对四个报告、Skill、业务案例、原型、代码、测试、部署、Git 和 27 份文档，给出证据路径。

## 8. 阶段说明

| 阶段 | 工作内容 | 主要交付物 |
|---|---|---|
| S01 | 台账与目录盘点 | 总任务台账、目录说明、文档资产清单、缺项清单 |
| S02 | 四个课堂报告 | 四份报告、图表源文件、课堂报告核查表 |
| S03 | 业务定位与全局分析 | 定位说明、结构图、总流程、角色表、开放问题台账 |
| S04 | 首个业务闭环 | 流程、泳道、状态、规则、异常、信息流和指标 |
| S05 | 系统需求与追踪 | SRS、术语表、用例、评审记录、追踪矩阵 |
| S06 | 测试前置 | 测试计划、场景、用例、数据和验收标准 |
| S07 | PC Web 原型 | 页面清单、导航图、原型、评审记录 |
| S08 | 详细设计 | 架构、模块、ER、表、API、权限、审计和部署设计 |
| S09 | 代码仓与实现 | 前后端代码、SQL、配置、测试代码及结果 |
| S10 | 系统测试与部署 | 缺陷、回归、测试报告、部署与用户运维材料 |
| S11 | 文档补齐与终审 | 27 份文档、资产清单、最终审计和汇报清单 |

## 9. 完成判定

Skill 不以文件数量作为唯一完成标准。每个“已完成”状态必须同时具备：

1. 可定位的交付文件。
2. 符合阶段要求的正文内容。
3. 与需求、设计、接口、数据表或测试的编号关联。
4. 对应的评审、构建、测试、运行或验收证据。
5. 已同步更新的总任务台账与追踪矩阵。

## 10. 安全与限制

- 不虚构访谈、会议、测试、部署、性能或验收结果。
- 不自动覆盖用户已有内容或未提交修改。
- 不在未经授权时删除文件、发布系统或操作远程仓库。
- 若文档与代码冲突，会登记冲突并要求确认，不擅自改变业务结论。
